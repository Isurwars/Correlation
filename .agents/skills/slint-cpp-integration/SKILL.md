# Slint C++ Integration & Data Binding Standards

This skill governs all C++20 integrations with the Slint UI framework: CMake build targets, controller architecture, thread-safe event loop synchronization, dynamic data models, and plot/image rendering.

## 1. CMake Target Integration

Build `.slint` markup into native C++20 targets via `slint_target_sources()`:

```cmake
find_package(Slint REQUIRED)

add_executable(correlation src/main.cpp)
slint_target_sources(correlation ui/AppWindow.slint)
target_link_libraries(correlation PRIVATE Slint::Slint correlation_lib)
target_compile_features(correlation PRIVATE cxx_std_20)
```

## 2. Controller Architecture & Initialization

C++ applications should instantiate generated Slint windows inside dedicated Controller/ViewModel classes (`AppController`, `PlotController`, `FileIOHandler`).

```cpp
#include "AppWindow.h" // Generated by slint_target_sources in CMake
#include <slint/slint.h>
#include <memory>

class AppController {
public:
    explicit AppController(slint::ComponentHandle<AppWindow> window)
        : window_(std::move(window)) {
        bind_callbacks();
    }

private:
    void bind_callbacks() {
        window_->on_run_analysis([this] {
            handle_run_analysis();
        });
    }

    void handle_run_analysis();

    slint::ComponentHandle<AppWindow> window_;
};
```

## 3. Thread-Safe UI Updates (`slint::invoke_from_event_loop`)

### Core Rule
Background threads computing pair distribution functions, reading trajectories, or executing OpenMP loops **must never** mutate Slint properties directly.

### Pattern
Use `slint::invoke_from_event_loop()` to dispatch back to the GUI event loop:

```cpp
void AppController::handle_run_analysis_async() {
    std::thread([this, window = window_] {
        auto result = run_pdf_calculation();  // Heavy compute off main thread

        slint::invoke_from_event_loop([window, res = std::move(result)] {
            window->set_progress(1.0f);
            window->set_analysis_status_text(slint::SharedString(res.summary));
        });
    }).detach();
}
```

## 4. Type Mapping & Data Models

### String Handling
Pass strings using `slint::SharedString` to prevent memory copies.

### Dynamic Collections (`slint::VectorModel`)
Use `slint::VectorModel<T>` wrapped in `std::shared_ptr` for dynamic lists, combo boxes, or tabular datasets:

```cpp
void populate_preset_list(AppWindow* window, const std::vector<std::string>& presets) {
    auto model = std::make_shared<slint::VectorModel<slint::SharedString>>();
    for (const auto& preset : presets) {
        model->push_back(slint::SharedString(preset));
    }
    window->set_preset_names(model);
}
```

### RAII Handlers & Callbacks
Bind Slint callbacks to C++ lambdas or member functions using weak references or RAII object lifetimes to avoid dangling memory traps.

## 5. Plot & Image Buffer Rendering

### SVG Buffer → Slint Image
```cpp
void update_plot_svg(AppWindow* window, const std::string& svg_data) {
    auto image = slint::Image::load_from_svg_data(
        slint::SharedString(svg_data)
    );
    window->set_preview_plot(image);
}
```

### Pixel Buffer Rendering
```cpp
void update_plot_pixels(AppWindow* window, const uint8_t* rgb_data, uint32_t width, uint32_t height) {
    auto pixel_buffer = slint::SharedPixelBuffer<slint::Rgb8Pixel>(width, height);
    std::copy_n(rgb_data, width * height * 3, reinterpret_cast<uint8_t*>(pixel_buffer.begin()));
    window->set_preview_plot(slint::Image::from_rgb8(pixel_buffer));
}
```

## 6. Unit Testing Controllers

Validate controller state mutations without opening physical display windows:

```cpp
#include <gtest/gtest.h>
#include "AppWindow.h"

TEST(AppControllerTest, SynchronizesPresetOptions) {
    auto window = AppWindow::create();
    AppController controller(window);

    // Verify initial state and property synchronization
    EXPECT_EQ(window->get_file_loaded(), false);
    EXPECT_EQ(window->get_progress(), 0.0f);
}
```
